# AI Use and Reflection — Lab 1

I used **Claude Code**, with **Claude Sonnet 5** as the underlying LLM, as my AI coding agent for Lab 1. The application code (health check, category seed, category list, tests) was built in an earlier session working from a written implementation plan. This later session, covered below, was mostly about getting the *engineering workflow* right: rebuilding the repository so it actually follows the required Issue → Project → feature branch → PR → peer review sequence, after my TA pointed out I needed to open and merge PRs one at a time with real review, not all at once.

## Reflection

The prompts that mattered most this session weren't about generating code — they were short corrections that kept the *process* honest: catching that Issues/Project had to exist before code, catching that a merged PR's Issue didn't actually close, and catching that a README the agent had reused from an old commit described features that weren't in that PR yet. An AI agent will happily execute a plausible-looking sequence of GitHub operations without checking it against the actual spec unless told to go re-read the spec directly — "go check the labsheet" did more than any detailed instruction I could have written myself.

**Note on scope:** database credentials used to run tests locally live only in the gitignored `server/.env` file, per `server/.env.example`, and were never committed.
