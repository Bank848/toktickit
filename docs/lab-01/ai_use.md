## Reflection

The prompts that needed the most follow-up were the ones translating someone else's feedback (a reviewer comment, a missed acceptance criterion) into a task, because I had to be precise about which exact behavior was wrong rather than just saying "fix the review comments." Vague prompts like an early "set this up" for the project foundation got a reasonable first pass but missed scope boundaries between branches, so being explicit about what NOT to build yet ended up being just as important as what to build. The git-workflow correction session was the biggest single improvement I made to how I prompt: rather than asking the agent to fix one branch at a time, I described the whole intended flow up front (branch targets, Kanban states, dependency order) so it could point out every mismatch in one pass instead of me discovering them one PR at a time.
